# Proposal: telemetry-proof-llm-efficacy

GitHub Issue: #16 (this repository). Sister change: PAMunb/rvsec#90 (`gh90-e3-decisive-run-setup`).

## Why

The 2026-07-29 decision session (source of record: `rvsec/rv-android/docs/20260729_propostas_melhorias_e3.md` §0 — design decisions in this change are FINAL, made by the project author on 2026-07-29 after adversarial verification by five disjoint-scope agents, **except the three tagged `2026-07-31`: B1's threshold, A10's mechanism, and O4, which are decided in this change on later evidence and are listed in design.md "Open Questions" as awaiting the author's ratification**) established three facts that this change answers:

1. **The evidential chain is broken at 3 of its links.** The chain decision → action → MOP-screen → violation is what the E3 experiment must prove, and today only 2.06% [2.00; 2.13] of steps are causally attributable to MOP guidance. The missing links are per-step: whether the current screen is a MOP screen (`mop_reach`), which selection channel actually picked the action (`pick_channel`), and whether the MOP boost changed the pick at all (counterfactual). All three are cheap to serialize — the data is already materialized per step — but none is in the trace.
2. **A quarter of all LLM calls are provably wasted.** 25.6% of LLM calls (10,081 of 39,341) re-emit a (state, coordinate) pair that already executed in the same run without producing a new state — and those repeats yielded **0 new states in 10,081 attempts** (Wilson CI [0.00–0.04]). The anti-repetition prompt instruction exists and is ignored; external evidence (Guardian, VeriGUI, LLMDroid) converges on the same conclusion: banning by subtraction beats instructing. A deterministic dead-pair ban is the highest-evidence efficacy fix available, and it comes with a built-in falsification gate.
3. **Telemetry defects bias every count.** 752 of 166,359 `[APE-STEP]` lines are corrupted by unescaped `\n` in widget text (0.45% bias, non-uniform across arms); `decision_source=WTG` conflates the MOP-frontier mechanism with generic WTG (three passes write the same `wtgBoost` field); screenshot failures silently trip the circuit breaker and disable the LLM arm on FLAG_SECURE apps (147 events, 4 APKs, 100% of the 57 breaker trips co-located) with no error line; and **338 of the 800 `aperv` runs (42.3%)** lost the UI-coverage dump. (The figure that circulated as "165/880" was an artefact of an unfiltered `n_summary_lines==0` query — 160 of its 165 rows are simply the two arms that never emit an LLM summary by construction. Corrected 2026-07-31: the real loss is 2.0×–2.5× larger, and its mechanism is not the one the design assumed — see A10.)

The jar feeds a decisive run (3 arms × 40 APKs × 30 min × 1 rep) that decides whether the LLM stays in the design. **There is no deadline**, and nothing below is scoped out on schedule grounds — A3, which an earlier revision named the designated cut, is implemented like everything else.

## What Changes

In dependency and risk order — B1 and the LLM-path fixes are what the decisive run's LLM arm cannot be interpreted without. This is not an importance ranking:

- **B1 — deterministic dead-pair ban** (~15 LOC + tests): when the LLM answer resolves to a pair already dead in this run, return null → SATA fallback (same path as `no_match`). Two ban keys: `llm_tap` by (abstract state, emitted coordinate); `matched` by (abstract state, element, eventType). Dead after **five** executions with `new_state=false` — one threshold for every widget class the ban covers, with **input-capable widgets (EditText, AutoCompleteTextView, both SearchViews) exempt at any strike count**, reusing `ApePromptBuilder.INPUT_CLASS_NAMES` rather than a second list. The exemption restores §0's `EditText` carve-out, which no finite k reproduces, and applies to the `matched` half only — an `llm_tap` has no matched widget (`matched_class=none` in 1,033 of 1,033 occurrences). It can only lower refusal, so the 27.5% below is an upper bound; the exact post-exemption share was not re-derived (k **re-selected 2026-07-31** after adversarial verification found the original sweep had been run on a key the ban does not use: it keyed both result types by `(state, pixel)`, but the shipped `matched` key is `Name`-level, under which k=3 refuses **37.6%** of LLM decisions rather than 27.9% — breaking the "under 30%" ceiling that was the stated reason for choosing it. k=5 under the shipped key refuses **27.5%** and restores the ceiling, losing 9 new states of 1,788 refused, against k=1's 59.2% which would leave the arm indistinguishable from its SATA fallback; the class-name exemption list is absorbed by arithmetic for every entry but one — it granted Switch/CheckBox/RadioButton k=2 where k=5 grants 5, while missing Spinner, Material/AppCompat subclasses and Compose entirely; `EditText` is the entry arithmetic cannot absorb, since an exemption is not a larger k, and it is retained as the input-capable carve-out above). Per-run, in-memory, never feeds `breaker.recordFailure()`, anchored on the stable pair — never a list index. Falsification gate: bucket D (dead-pair repeats) must fall to ≈0 BEFORE new-state gains are evaluated; if D≈0 and new states do not rise, B1 is judged ineffective. Scope limit: the ban runs after the LLM call returns, so it raises yield per decision but saves no latency — it does not address the LLM arm's measured throughput deficit (0.622× the algorithmic arm's steps).
- **B6(i) — ActionType filter in the containment pass** (~10 LOC): when the LLM says `click`, the mapping requires `MODEL_CLICK` (today `click` executes CLICK only 80.9% of the time).
- **B6(iii) — per-request tool schema** (~10–20 LOC, touches `SglangClient`): the tools array is currently built once in the constructor and always contains `type_text`, while the system message includes `type_text` conditionally — the model is offered a tool the prompt says does not exist. The tools list becomes per-request, `type_text` present only when the screen has an input field.
- **B6(iv) — fixTextEdit (Guardian mechanism)**: on EditText, remove bare click from the LLM action space — an LLM `click` resolving to an input widget becomes a text-entry action (where from the LLM, what generated by the harness). Attacks the measured `type_text≈0` collapse.
- **N1 — identifiers in prompt element lines** (~1–5 LOC): element lines never render an identifier when text and content-description are empty. Measured: prompts without identifier hit 33.1% vs 71.4% with; ImageView 0/210 is a prompt bug.
- **B4 — edge-based snapping** (~6–10 LOC): replace centre-distance with point-to-rectangle distance (clamped dx/dy) in the snap loop. The `ape.llmSnapTolerancePx` property stays; raising it to 150 is an rv-android config decision gated on B1 (out of scope here).
- **A4 — serialize `mop_reach`** (~3 LOC): `activity_has_mop=0|1` on every `[APE-STEP]` line and on the `[APE-OUTCOME]` target line, via the existing O(1) `MopData.activityHasMop`.
- **A5 — `pick_channel` field** (~10 LOC): every `[APE-STEP]` line names the selection channel that picked the action, from a fixed enum — today the separation is regex over free text.
- **A6 — un-alias `wtgBoost`** (~15 LOC): `MopFrontierPass` gets its own `mopFrontierBoost` field on `ModelAction`, its own decision-source value, and its own `[APE-STEP]` field — `decision_source=WTG` stops conflating MOP-frontier with generic WTG.
- **A8 — escape newlines in `[APE-STEP]`** (~5–10 LOC): widget text with `\n` breaks the line (752/166,359 lines). Also makes `[APE-LLM-PROMPT]` line-parseable.
- **A7 (jar part) — screenshot-failure telemetry** (~1–10 LOC): emit `[APE-LLM-ERROR] cause=screenshot activity=<current>` where today the branch is intentionally silent; discriminate the failure stage in `ScreenshotCapture`. Evidence: 147 events in 4 FLAG_SECURE APKs; 100% of 57 breaker trips co-located — the breaker silently disables the LLM.
- **A10 — hoist the coverage dump ahead of the model serialization** (~10 LOC): today the dump is the **last** instruction of a chain whose third step serializes the exploration model to `/sdcard`, and **330 of the 338 lossy runs are cut exactly there**, on the `Save graph data to /sdcard/sata-…` line. Emitting the dump before `saveGraph` recovers **333 of 338 (98.5%)**. The original A10 design — an idempotent JVM shutdown hook — recovers **zero** on this failure path, and the reason is not the signal but the sink: the trace is the host's `adb` stdout, which the harness SIGKILLs and closes before any device-side signal is delivered, so the hook may run but its output has nowhere to land. Revised 2026-07-31.
- **O4 — `patched=<bool>` on `[APE-STEP]`** (~10 LOC): `GUITreeBuilder.patchGUITree` (default on, and controllable by **no** experimental arm) rewrites `GUITreeNode.clickable` plus the DOM mirror, while `ActionPatchNamer.generatePatch` prints only post-patch values — so no artifact distinguishes a click on a natively clickable widget from a click on one the patch fabricated. Offline joins can only estimate the share through a `(class, resource-id)` **type** proxy that yields a point estimate of 36.0% at type level (19.4% rests on a different denominator, and no lower bound above 0 is derivable from this corpus — the pair is not an interval), and even that estimate is conditional on the patch log being complete (64 runs carry 6,561 clicks and not one patch line). One bit per step makes the quantity exact and removes the condition. Purely additive; reads nothing back.
- **B7(i) — make the stagnation trigger fire** (~5 LOC): the exact-equality check over a counter that resets on every new edge is a 1-step window per episode, virtually never firing. Fix: `>=` with re-arm semantics (fire once per stagnation episode).
- **K10 — docs fix**: ape `CLAUDE.md` says `activityTriggerEnabled` default `false`; `Config.java:165` has default `true`. Correct the doc (current-state, P4).
- **A3 — per-step counterfactual (DESIGNATED CUT — last work group, optional-if-time)** (~50–80 LOC + dedicated test): `cf_action` + `cf_changed` on `[APE-STEP]`: what the selection would be with `mopBoost`/`mopFrontierBoost` zeroed. Covers all 4 pick sites, MUST NOT perturb the seeded RNG stream (INV-EXPL-14). Honest caveat: 1-step myopic — establishes the divergence point, not the cumulative effect. Smoke invariant: in a MOP-off arm, `cf_changed` must be 0 always.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `llm-routing`: dead-pair ban (B1); ActionType filter, edge snapping, fixTextEdit in coordinate mapping (B6(i), B4, B6(iv)); per-request tool schema at the router (B6(iii)); stagnation trigger re-arm (B7(i)); screenshot-failure error line and prompt-log sanitization (A7, A8).
- `llm-prompt`: identifier presence in element lines (N1).
- `llm-infrastructure`: per-request tools on `SglangClient` (B6(iii)); capture-failure cause seam on `ScreenshotCapture` (A7).
- `action-selection`: `activity_has_mop`, `pick_channel`, line well-formedness on `[APE-STEP]` (A4, A5, A8); clickability-patch provenance on `[APE-STEP]` (O4); per-step counterfactual (A3, optional).
- `scoring-pipeline`: `mopFrontierBoost` de-aliasing (A6); `activity_has_mop` on `[APE-OUTCOME]` (A4).
- `ui-coverage`: dump emitted before model serialization (A10 — the shutdown-hook design is withdrawn; see design D9).

`mop-guidance` is NOT touched: A4 consumes the already-specified O(1) `MopData.activityHasMop`.

## Impact

- **Components**: `LlmRouter`, `SglangClient`, `ScreenshotCapture`, `ApePromptBuilder`, `StatefulAgent`, `SataAgent`, `ModelAction`, `MopFrontierPass`, `UICoverageTracker`, `GUITreeNode` (O4), `CLAUDE.md`.
- **Experiments**: one rebuild only; the jar feeds the decisive run (3 arms × 40 APKs × 30 min × 1 rep) that decides whether the LLM stays in the design. The instrumentation items (A-group) are arm-neutral telemetry; the efficacy items (B-group, N1) change LLM-arm behavior only — the algorithmic arms are untouched except for B7(i) (stagnation trigger is LLM-gated) and A6 (attribution label only, no priority change).
- **Out of scope (decided in §0)**: B6(ii) scroll in the schema (rejected for now); B8 LLM-as-boost (deferred post-Phase 1); B9/N7 WTG pathfinding (deferred — reopening condition per §0: reassess if Phase 2 shows screen reach is the dominant bottleneck); B3 tolerance raise to 150 px (rv-android config change, gated on B1); anything in rvsec-gator; the LLM dose for the decisive run (settled on the rv-android side at `llm_percentage=0.7`). The rv-android companion change (A1 MOP-off arms, A9 clock↔logcat join, B2, B3, N4, N6, O3, the capture grace window) is a separate change in that repository.
- **Dependency this change has on its sister, stated because it runs in the other direction from the usual one**: verification gate 17.4(a) exercises the **MOP-off arm**, which is defined by `gh90-e3-decisive-run-setup` task group 1. This repo builds the jar; it cannot check off gate (a) until that arm exists. Gates (b)–(f) are independent of it.
