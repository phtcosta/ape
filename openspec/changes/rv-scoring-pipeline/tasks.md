## 1. Characterization (BEFORE any refactor)

> **Granularity (decided 2026-07-08).** `adjustActionsByGUITree()` is deterministic — it makes no `getRandom()` call (the RNG lives downstream in epsilon-greedy selection). Parity of the scoring path is therefore an exact input→output equality; no seed is needed to pin it. A whole-engine golden would require constructing live `GUITreeNode` + `Graph` + `GUITree` fixtures, which this repo has consistently deferred to device smoke (pure static seams are unit-tested, live-node wiring is not — see `ActivityFrontierTest`, `FormCompletionTest`, `ModelActionTest` notes). Characterization is therefore captured at the **seam granularity that is JVM-feasible**; the whole-engine wired golden is the device smoke (task 7.6), and the byte-identity of the extracted base loop is task 3.7. The per-pass wiring tripwire is tasks 3.1–3.6 (each per-pass test reproduces its inline block, written test-first before the block is moved).
