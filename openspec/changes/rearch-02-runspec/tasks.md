- [x] 4.3 Create `RunSpecEcho.emit(RunContext, PrintStream)`: `RUN_START` object per design D-7 (`type,v,run_id,t0,seed,agent,preset,features,params,inert,corpus_basis,digest,props_digest,build`); wire into `Monkey.run` immediately after `RunContext.initialize`, before `MonkeySourceApe` construction. Two corrections folded in at apply time: `t0` was in the run-spec delta's requirement but missing from this list and from D-7's example (it is the emission instant stage 4's relative offsets resolve against), and the parameter is the **context**, not the spec — `run_id` is D-12's, not `RunSpec`'s
- [x] 4.3a Echo `ape.corpusBasis` as `corpus_basis`, omitted when absent, read by nothing (INV-RUN-03). The *registration* half of this task landed early, in group 1: `KeyOwnership` already declares `KEY_CORPUS_BASIS` as resolver-owned beside `KEY_RUN_ID`, which is what task 1.2's "the third registered by task 4.3a" anticipated. Group 4 added only the echo. It exists because this study has counted its analysis basis as 163, 181 and 219 applications in different documents; one hash per run ends the re-derivation. Do **not** add per-application static facts here — the basis is a property of the corpus, not of the plan, and per-app copies would write the same truth in forty places
- [x] 4.3b Record in the verification notes what `RUN_START.seed` actually carries. **This task's original premise was wrong and was corrected at apply time.** It said the field would be empty under the current deployment. It will not be: the harness appends `-s` only when a seed is configured (`tool.py:1380-1382`) and none is — but `Monkey` then manufactures one, `mSeed = System.currentTimeMillis() + System.identityHashCode(this)` (`Monkey.java:679-681`), *before* the `--ape` branch, and builds both `mRandom` and `RandomHelper` from it. So the field is always full, and what the campaign lacked was never a seed but **control over** the seed. Two consequences: a run is individually reproducible from its own trace as of this stage (bounded by device timing and the one unseeded `Random` that task 5.1 closes), and the `rearch-05` item is not "supply a seed" but "make the seed *designed*" — a deterministic function of (application, arm, replica), never one constant for the campaign, which would collapse the three-replica variance estimate every effect size is read against. The run-spec delta's `Run Identity and Seed` requirement and its scenario carry the same correction
- [x] 4.4 Unit tests: echo content reconstructs each of the four preset plans (report test 9.6) — written as an actual re-resolution of the record's `params` (plus `inert` at each key's neutral value) back through `RunSpec.resolve`, asserting equal digests, rather than as a field checklist; single-line + escaping round-trip on hostile values, both in the serializer and end-to-end through an operator-supplied string parameter; `inert` list content; double-initialize throws. **The ordering check is a source-order guard over `Monkey.java`, not the stream capture this task first named**: the statements it orders are `AndroidDevice` initialisation and the `MonkeySourceApe` constructor, both of which need a device, so a JVM stream capture would have restated the ordering instead of executing it.
